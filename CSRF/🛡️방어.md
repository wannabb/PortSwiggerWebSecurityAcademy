# 🛡️ CSRF 방어 기법 정리

## 1. CSRF 토큰 활용
  
> [!NOTE]
> CSRF 방어 중 가장 표준적이고 강력한 방법으로, 예측 불가능한 고유 토큰을 검증하여 요청의 유효성을 판단한다.

### 핵심 원리
* 사용자 세션마다 `예측 불가능한 난수`를 생성하여 `form` 요소나 `Header`에 포함시킨다. 
* 서버는 요청 수신 시 제출된 토큰과 세션에 저장된 토큰이 일치하는지 검증한다. 이때 메소드와 상관없이 검증이 이루어져야 하며 토큰이 없다면 일치하지 않는 것과 같은 처리를 해야 한다.


> [!TIP]
> * 예측 불가능 난수를 생성하기 위해 `CSPRNG`를 사용한다.
> * form 요소에 토큰을 포함할 경우 공격자의 HTML 조작 및 데이터 탈취를 막기 위해, 폼 내부에서 일반 입력 필드나 사용자 입력 데이터보다 상단(초반)에 배치하는 것이 좋다.
> * URL의 쿼리스트링이나 쿠키로 토큰을 전송하는 방식은 지양해야 한다.  

## 2. SameSite

### SameSite를 안전하게 설정하는 법
* 합당한 이유가 없다면 쿠키들의 SameSite 옵션은 기본적으로 `strict`로 설정 하자.
* 브라우저마다 SameSite의 기본 설정이 다르기에 발급하는 각 쿠키에 SameSite 제한을 명시적으로 설정하는 것이 좋다.
* `SameSite=None` 설정은 절대 피해야함.

> [!CAUTION]
> SameSite가 안전하게 설정되어 있음에도, SameSite Cross-origin 공격에는 무력하다. site는 `Scheme+eTLD+1` 이고  origin은 `Scheme+Hostname+Port`라는 차이가 존재하며 SameSite는 site를 기반으로 체크하기에 당연한 것이다.
> 따라서, sibling domain의 보안 취약점을 잘 점검하는 것도 중요하고 가능하다면 보안에 취약한 콘텐츠가 존재하는 사이트는 별도의 사이트로 분리하는게 좋다.
