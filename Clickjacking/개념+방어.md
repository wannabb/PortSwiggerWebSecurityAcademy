# Clickjacking 

## 1. 개요 (Overview)
- **정의:** iframe 창을 투명하게 만들어 공격자 사이트위에 겹친 후 사용자로 하여금 특정 상호작용을 유도하게 하는 취약점.

## 2. 공격 메커니즘 (Attack Vector)
 기본적으로 CSS를 이용해 배치한다. 가장 간단한 clickjacking 취약점을 이용하는 코드는 다음과 같다.
 ```html
<html>

<head>
  <meta charset="utf-8">
  <title>lab-basic-csrf-protected</title>
  <style>
    .container {
      position: relative;
      width: 500px;
      height: 890px;
    }

    .decoy {
      position: absolute;
      top: 865px;
      left: 65px;
      z-index: 1;
    }

    .target {
      position: absolute;
      top: 0;
      left: 0;
      width: 100%;
      height: 100%;
      opacity: 0.1;
      z-index: 2;
    }
  </style>
</head>

<body>
  <div class="container">
    <div class="decoy">Click me</div>
    <iframe class="target"
      src="https://target"></iframe>
  </div>
</body>

</html>
```
수동으로 decoy div의 위치를 타겟 웹사이트의 특정 상호작용을 일으키는 버튼 위에 겹치도록 지정해야한다. 그리고 `z-index`값의 차이를 두며 `opacity`를 0에 가깝게 설정하여 보이지 않으면서 가장 위에 오도록 한다. 


## 3. 대응 방안 (Mitigation)
 1) **X-Frame-Options:** iframe에 적재 조건을 브라우저에게 명시해주는 헤더이다. 
    - deny: 적재불가
    - sameorigin: sameorigin일 경우에만 적재가능

 2) **Content-Security-Policy:** CSP는 xss나 clickjacking 같은 공격을 탐지 및 완화한다. clickjacking을 방지하기 위해 쓰이는 정책은 `frame-ancestors`가 있다.
    - 사용예) Content-Security-Policy: frame-ancestors 'self';
    - 값으로 `'none'`, `'self'`, `특정사이트(공백으로 구분)`를 줄 수 있으며 'none'은 X-Frame-Options의 deny와, 'self'는 sameorigin과 같다.

>> [!NOTE]
>> 추가로 Frame burster script도 존재하긴 하나 해당 방어는 자바스크립트로 구현되는 것이기에 iframe의 sandbox 옵션을 설정하면 쉽게 우회되는 취약한 방어다. 클릭재킹을 방지하기 위해서는 X-Frame-options와 CSP를 적절히 조합하여 다층의 방어를 쌓는데 베스트이다. 그냥 보기에는 똑같아 보이지만 CSP는 유연한 설정이 가능하다는 특징이 있으며 CSP와 X-Frame-Options가 동시에 있다면 CSP가 우선순위를 가진다. 또한, CSP는 최신 기술이기에 구형 브라우저는 CSP를 이해할 수 없기에 X-Frame-Options의 중요도가 부각된다.
