# **Cross-Site WebSocket Hijacking (CSWSH)**

## 1. 개요 (Overview)
- **정의**: 크로스 사이트 간 웹소켓 통신 환경에서 웹소켓 핸드셰이킹 과정 중 CSRF 취약점을 이용하는 공격이다. 이를 통해 피해자의 의도하지 않은 행동을 유도하거나 민감한 데이터를 유출할 수 있다.

## 2. 공격 메커니즘 (Attack Vector)
- 공격 메커니즘을 이해하려면 선행 지식으로 웹소켓에 대한 이해가 필요하다.
- **웹소켓의 목적**: 브라우저와 서버 간 양방향 실시간 데이터 통신을 가능하게 한다.
- **웹소켓의 특징**:
  - 지속적 연결을 통한 `실시간성` 및 `저지연성` 제공
  - `양방향 비동기 통신` 지원
  - HTTP 헤더 오버헤드 없이 `가벼운 프레임` 단위로 데이터 송수신
  - 기본적으로는 SOP의 적용을 받지 않아 cross-origin 연결을 허용한다. 
- **웹소켓 핸드셰이킹**:
  1. `Upgrade: websocket` 헤더를 포함한 HTTP 요청으로 최초 연결 시도
  2. 서버가 요청을 승인하면 `101 Switching Protocols` 응답 반환
  3. 핸드셰이크 완료 후 `ws://` 또는 `wss://` 프로토콜로 전환하여 양방향 데이터 송수신 수행
- **취약점 발생 조건**:
  - 세션 처리를 위해 첫 단계(HTTP `Upgrade` 요청)에서 세션 쿠키를 사용하지만, CSRF 토큰이나 기타 예측 불가능한 검증 값이 존재하지 않는 경우 CSWSH 취약점이 발생할 수 있다.
## 3. 방어
- `wss://` 프로토콜 사용 권장.
- `웹 엔드포인트 URL`은 `하드코딩`하며, 사용자가 제어가능한 값을 해당 URL에 포함시키면 안된다.
- CSRF 공격으로 부터 웹소켓 핸드셰이크 메시지를 보호하여 CSWSH을 방지한다.
- 웹소켓을 사용하여 주고 받는 메시지는 신뢰할 수 없으며, 항상 인코딩을 거쳐 안전하게 처리해야 한다.
